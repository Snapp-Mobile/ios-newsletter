## Swift

### [Google Analytics for Firebase iOS SDK outage on September 28, 2026](https://firebase.blog/posts/2026/10/firebase-analytics-outage/)

[Jerome Mourits](https://www.linkedin.com/in/jerome-mourits/){: .author}, [Don Kahn](https://www.linkedin.com/in/donkahn/){: .author}

A two-line cleanup left a dangling configuration reference, and suddenly apps using the Google Analytics for Firebase SDK were crashing when they fetched the bad payload. The outage lasted just over two hours, but the postmortem is useful beyond Firebase: validate remote data at the client boundary, catch orphaned config in CI, and don’t let a green server dashboard stand in for client health. The queued crash reports also explain why the incident looked like it lingered after the rollback.

### [Optional Chaining: Let Absence Flow Through an Expression](https://ivantokar.com/posts/optional-chaining-let-absence-flow-through-an-expression/)

[Ivan Tokar](https://bsky.app/profile/ivantokar.bsky.social){: .author}

Optional chaining is more than a tidy way to dodge nested `if let`s. It preserves the distinction between a missing value and a present `false`, and it can skip the right-hand side of an assignment entirely when an earlier link is `nil`. That’s a small but important behavior to keep in our heads—especially with dictionary subscripts, where “do nothing if missing” is very different from “create a value.”

### [Advanced macro technique #2: Type inference](https://www.pointfree.co/blog/posts/233-advanced-macro-technique-2-type-inference)

[Point-Free](https://www.pointfree.co/about){: .author}

Swift macros see syntax, not the compiler’s static type information, which makes generating APIs from inferred properties awkward. Point-Free’s solution is delightfully indirect: generate a protocol with an associated type, then let a witness type infer that type from the property’s default value. The macro can use the inferred type in its generated initializer without asking users to sprinkle annotations everywhere. A neat technique for anyone building macros that generate real types or functions.

## UI / UX

### [Fix misaligned paging in SwiftUI scroll views](https://nilcoalescing.com/blog/FixMisalignedPagingInSwiftUIScrollViews/)

[Matthaus Woolard](https://bsky.app/profile/hishnash.bsky.social){: .author}

If SwiftUI paging drifts a little farther off with every swipe, check the spacing in your `LazyHStack` before reaching for a custom paging solution. `.paging` measures stops against the scroll container, while the stack’s default gaps quietly shift the pages out of place. Set the spacing to zero; if you still want breathing room, put padding inside each page before `containerRelativeFrame`. One of those fixes that’s obvious once you know where to look.

### [Positioning SwiftUI views around the fold on iPhone Duo](https://nilcoalescing.com/blog/PositioningSwiftUIViewsAroundTheFoldOnIPhoneDuo/)

[Natalia Panferova](https://bsky.app/profile/natpanferova.bsky.social){: .author}

A fold is not just another narrow screen: content that crosses it can be hard to read or tap, and scrolling won’t move a vertical fold out of the way. SwiftUI’s `reservedRegions` API lets a layout inspect the fold’s frame and place grid columns on either side of it. The clever extra is including inactive regions too, so the number of columns can stay stable as the device folds. Worth a look now if our layouts need to adapt to more than a flat rectangle.

### [SwiftUI Performance: Find Redraws in Xcode Instruments](https://www.avanderlee.com/swiftui/swiftui-performance-xcode-instruments/)

[Antoine van der Lee](https://bsky.app/profile/avanderlee.com){: .author}

When a SwiftUI screen feels sluggish, Instruments can show which view bodies are updating, how much time they take, and what state change triggered them. The practical advice here is to profile a short, focused interaction in a Release build, then inspect both the update hierarchy and the per-update table—lots of individually cheap redraws can still pile up on the main thread. And yes, measure again after changing the code; vibes are not a performance metric.

### [How native SwiftUI controls look different in iOS 26](https://sarunw.com/posts/swiftui-native-controls-ios-26/)

[Sarun W.](https://x.com/sarunw){: .author}

Build with the iOS 26 SDK and run on iOS 26: plenty of familiar SwiftUI controls change appearance without a line of custom styling. Buttons get rounder, toolbars pick up glass backgrounds, tab bars float, and partial-height sheets gain inset edges. The useful reminder is to check what the system already gives our apps before adding custom glass effects—though you’ll want to test the whole interaction, not just the controls at rest.
